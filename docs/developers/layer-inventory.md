# Branch, Cone, and Feature Inventory

What each file in `R/branches/`, `R/cones/`, `R/features/` and `R/trunk/` is for, and the caveats that matter when reusing it. Function names only: the signatures are generated into [functions.md](functions.md) from the source, so they cannot drift here. Update a row when a file's purpose or its main functions change.

nested alternatives and inherited citations for display. Its feature companion
exposes `format_shared_requirement_preview(reference)` and
`capture_shared_requirement_sources(reference, directory, fetch)`. These are
reference/candidate artifacts, not runtime scheduling or student audits.

directory, catalog_id = NULL, include_courses = TRUE, resume = FALSE,

`compare_degree_catalog_scans(before, after, output)` and verified

and `catalog_review_detail(payload, item_id)`.

receipts and JSON pointers, including embedded concentrations. Review artifacts
are verified before cache lookup; original source blobs are verified on Inspect.

`catalogReviewUI(id, catalog, roadmaps)` / `catalogReviewServer(id, root, active, catalog, roadmaps,
review_root, shared)` module mounts under Admin > Data & Usage.

`catalogNormalizationUI(id)` / `catalogNormalizationServer(id, root, capture_root, active, draft_dir)` is under
